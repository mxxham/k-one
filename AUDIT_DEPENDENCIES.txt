CROSS-CUTTING CONCERNS
======================

1. AUDIT LOGGING (ActivityLogger)
   - 25+ handlers use ActivityLogger::log()
   - Tracks: user, action, reference (table/id), timestamp
   - Tables: activity_logs
   - Pattern: All write operations logged immediately

2. ROLE-BASED ACCESS CONTROL (Auth)
   - api_require_auth() → any authenticated user
   - api_require_write() → operator+ role
   - api_require_admin() → admin role only
   - Used in handlers via middleware functions

3. DATABASE TRANSACTIONS
   - Inbound::complete() - transaction wraps complete flow
   - Outbound::ship() - transaction wraps shipment
   - Stock::hold/release - transactions wrap ledger inserts
   - Pattern: Rollback on exception

4. ERROR HANDLING
   - json_err(message, code) for API errors
   - exception throwing in services
   - Try-catch at handler level
   - Consistent HTTP status codes

5. PALLET/UOM CALCULATIONS
   - PalletHelper handles all conversions
   - Product.uom_type + uom_per_pallet define capacity
   - calculatePallet() called in Inbound, Outbound, Picklist

6. FEFO COMPLIANCE
   - FefoAllocator::allocate() sorts by expiry_date ASC
   - Used in Outbound::getFEFOAllocation()
   - Used in Inbound (receiving side)
   - Critical for compliance


POTENTIAL ISSUES IDENTIFIED
============================

1. DUPLICATE HANDLERS (MEDIUM PRIORITY)
   - wave.php and waves.php both handle wave operations
   - wave has 7 actions; waves has 5 (subset)
   - Recommendation: Consolidate waves into wave; remove duplicate

2. NAMING AMBIGUITY (LOW PRIORITY)
   - Picklist (class) vs PicklistService (orchestrator)
   - Suggests rename PicklistService → PicklistOrchestrator

3. LIGHTWEIGHT SERVICES (REFACTOR OPPORTUNITY)
   - OrderService: only 5 methods, could merge into Outbound
   - StagingService: only 2 methods, could merge into Stock
   - TaskAssignmentService: wrapper around db queries, minimal logic

4. CROSS-DOCK COMPLEXITY (MODERATE PRIORITY)
   - Inbound items link to Outbound orders via cross_dock_outbound_order_id
   - Circular reference between Inbound ↔ Outbound (by design)
   - Ensure transaction isolation; no deadlock observed

5. REPORT SERVICE CENTRALIZATION (DESIGN NOTE)
   - Report aggregates data from 7 other services
   - High fan-in; any change to Stock, Inbound, Outbound affects Report
   - Recommend: Use event logging or separate reporting schema

6. IMPORT HANDLER COMPLEXITY (MEDIUM)
   - Multiple file format support (xlsx, xls, csv)
   - Async processing via auto_async action
   - Delegates parsing to import_helpers.php
   - Should add unit tests for file format handling
